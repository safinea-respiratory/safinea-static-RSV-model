# Epidemiological data

Two upstream files from RespiCompass target-data covering **28 EU/EEA
countries**, plus **derived two-season versions** generated from them.

### Provenance

| | |
|---|---|
| Source | [RespiCompass `target-data`](https://github.com/european-modelling-hubs/RespiCompass/tree/main/target-data) |
| Commit | `592d122d4a1a33c50ed3c6ecf1128a214a91a3c3` |
| Committed | 2026-08-31 |
| Retrieved | 2026-08-31 |
| Season | 2026/27 |

Vendored deliberately — the model reads nothing over the network, so runs stay
reproducible and offline.

**Age bands are defined by these files, not by the code.** Whatever labels
appear in `age_group` become the model's bands and flow through to the
submission's `pop_group`. The config only *references* them; any band named in
the config but missing from the data is a hard error at load.

**Date formats are declared, not guessed** (`input_date_formats` in the config).
R's `as.Date("01/09/2025")` does not return `NA` — it silently returns
`0001-09-20`. Declared formats plus a plausible-year check make that class of
silent corruption impossible.

## ⚠ The `_2seasons` files are DERIVED, not real

`hospitaladmissions_2seasons.csv` and `hospitalburden_agegroups_2seasons.csv`
are generated by [`scripts/make_two_seasons.R`](../../scripts/make_two_seasons.R).
**Season 2 is synthetic** — an exact copy of the upstream 2026/27 season shifted
forward 364 days. Do not mistake it for hub data.

They exist so the model can be exercised over a multi-season horizon: with the
adult campaign running only in season 1, season 2 shows that cohort's protection
waning a year on, which a single season cannot reveal.

Both carry a `season` column (`2026/2027`, `2027/2028`). The model derives
season from the burden window dates and only *cross-checks* the column, so it
works on the upstream single-season files too — point `epi_weekly_file` and
`epi_burden_file` at the unsuffixed names to run one season.

**Why 364 days.** Exactly 52 weeks, so every date stays a week-ending Sunday and
season 2's first week (`2027-09-05`) lands exactly 7 days after season 1's last
(`2027-08-29`). A calendar-year shift would not: 2028 is a leap year, so +1 year
is 365 or 366 days and would break the weekly grid. Births use the opposite
convention — see [../population/README.md](../population/README.md).

The generator validates its own output: contiguous 7-day grid, no duplicate
weeks, non-overlapping burden windows, season totals matching, and margins
reconciling within each season.

## hospitaladmissions.csv

Weekly aggregate RSV hospitalisations, all ages. One row per (country × week).

| Column | Type | Description |
|--------|------|-------------|
| `country` | string | Country name — selected by `countries` in the config |
| `age_group` | string | Always `total` — unused by the model |
| `target_end_date` | date | Week-ending date (Sunday). Used directly, no offset applied |
| `year_week` | string | ISO year-week, e.g. `2026-W36` — unused |
| `week` / `year` | integer | ISO week and year — unused |
| `weekly_rsv_hospitalisations` | integer | Total RSV hospitalisations that week |
| `season` | string | *(derived files only)* e.g. `2026/2027` |

**52 weeks per country**, `2026-09-06 → 2027-08-29`, contiguous at 7-day
intervals. An earlier revision of this file omitted ISO week 53
(`2027-01-03`); the current one includes it, and `horizon` is now a complete
`0..51` with no skipped integer.

**Example**

```
country,age_group,target_end_date,year_week,week,year,weekly_rsv_hospitalisations
Ireland,total,2026-09-06,2026-W36,36,2026,4
Ireland,total,2026-09-13,2026-W37,37,2026,7
```

## hospitalburden_agegroups.csv

Age-stratified RSV hospitalisation totals over the season. One row per
(country × age band × season). These are **absolute counts, not proportions** —
the model uses them directly.

| Column | Type | Description |
|--------|------|-------------|
| `country` | string | Country name |
| `age_group` | string | Age band label — defines the model's bands |
| `start_date` / `end_date` | date | The burden window |
| `total_rsv_hospitalisations` | integer | Total in that band over the window |
| `season` | string | *(derived files only)* e.g. `2026/2027` |

### Age bands

`0-2mo, 3-5mo, 6-11mo, 1-4, 5-17, 18-59, 60-64, 65-69, 70-74, 75-79, 80+`

The finer adult bands are what make an age-targeted adult campaign expressible.
A 75+ programme is `["75-79", "80+"]` — no population-fraction approximation,
which would otherwise bias the estimate because RSV hospitalisation risk rises
steeply with age.

### ⚠ Time resolution

This file gives **one total per band per season**. The fixed-margin sampler
therefore draws a single (weeks × ages) table per season, so the age mix is
constrained only *across* each season, not within it.

That is an honest reflection of what this data constrains — but the consequence
is real: the per-week age split carries a median coefficient of variation of
roughly **0.4** across draws. Weekly *totals* remain exact in every draw (they
are a fixed margin), so all-ages outputs are unaffected. It is the age-specific
rows that carry this uncertainty.

**Example**

```
country,age_group,start_date,end_date,total_rsv_hospitalisations
Ireland,0-2mo,2026-08-31,2027-08-29,1035
Ireland,80+,2026-08-31,2027-08-29,760
```

Marginals must reconcile within each season: for Ireland 2026/27 both files sum
to **5,265**. When they disagree the sampler scales one side (`reconcile` in
`simulate_weekly_age_fixed_margins`).
